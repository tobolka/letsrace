# Czech cycling 2027: completed production import — 31 October 2026

## Result

**13 new public race records, 23 existing records enriched, 2 main-batch records already correct, and 1 Lesák duplicate merged with relationships and recoverable history preserved.** The 23 updates include two retained noncompetitive rides and the hidden Lost Ride draft. The reviewed main batch therefore has **35 publicly listed races, two rides outside the race calendar, and one TBC draft**. Two additional existing races were checked unchanged; two additional uncertain discoveries were saved in the review queue and one recreational event was excluded.

The supplied request contains 26 named event groups, despite the headline counts of 22; all 26 were processed. Twelve additional groups were implemented/reviewed with the batch, and five more discoveries assessed: **43 investigated groups total**. Route variants are included within their event where the existing model supports that. Bike Paradise and Půl Paradise keep their two pre-existing independent route records; no duplicate was created.

All production changes were executed, not left as a proposed script. Verification snapshots, complete previous values and current values are stored beside this report.

- Production project: `xlomrxswdcekarazaahx` / letsrace. No schema migration, no authentication or user-data change.

- **13 inserted public race records**, **23 updated event records**, **4 existing correct groups** (2 main + Montes + Vabank), **1 duplicate merged**. Two additional candidates saved as `waiting`.

- 689 field-level audit facts plus an atomic batch-complete marker were recorded. Existing overrides are merged, never discarded. Verified identity, dates, classification, location, routes and registration decisions are locked against later automatic replacement.
- Existing source identifiers, series links and organiser sources were inspected; this schema has no separate organisers/aliases/variants tables. `event_sources`, `event_series`, `event_categories`, existing slugs, the protected fields and merge history are the native mechanisms. New UltraBikers rounds link to its existing series.
- Transaction guarded by advisory lock, before-value assertions and same-name/date/slug duplicate detection. It is idempotent via a completion marker. Full snapshots are recoverable in the report folder; standard `app_merge_events` preserves source evidence, user relationships and merge history.
